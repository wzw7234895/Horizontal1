# 当前组内测距与跨组高度方案

更新时间：2026-11-09。本文件描述当前代码默认行为，不把名义试算值当作现场验收结果。

## 约束与计算边界

- D01/D03 固定安装在大车，D02/D04 固定安装在小车。**固定**指同组两镜头安装后的光心间距、方向差不随运行改变，不是两镜头处于同一位置或方向。
- 小车相对大车只做水平平移；不从传感器或图像估计两组之间的水平位置。四台相机不能再按一套刚性组处理，配置 `all_cameras_rigid=false`。
- 每个目标秒从四路视频各取一帧。允许秒内曝光差，按业务指定忽略该项误差；这不是同步精度验收结论。
- 四路画面都参与 A/B 的视觉候选搜索：参考组另一相机使用组内几何约束，跨组两路使用图像特征及数据驱动的极线关系提出候选。跨组视觉候选本身没有米制尺度，也不作为跨组固定基线。
- A、B 都可由同一组的两路相机看见并匹配时，各自三角测量，组内计算 `||X_B-X_A||` 和 `Z_B-Z_A`。即使 A/B 最初在另一组的参考图中选定，只要视觉转移到目标组的两台相机并通过组内三角检查，也可由目标组测距。整体水平平移不改变组内距离。
- A、B 分属两组时，**每个点必须在其所属组的两路相机中可见同一物理点**。分别三角测量得到组内 `Z`，用离线实测的竖直高度基准偏移对齐，再求高度差；`distance_m=null`。小车水平位置未知时不输出跨组完整三维距离或水平覆盖关系。
- 任一点缺少同组第二视角、可见最低点/头顶并非同一物理点、或标定/重投影检查失败时输出未知。单目同平面估算只在显式 `--assume-same-plane` 时用于离线试算。

## 离线输入与复用

1. 对四台相机实测内参 `K`、畸变 `D`，固定焦距、分辨率和裁剪。使用有已知米制尺寸、分布在不同高度的控制点，对 D01/D03 以及 D02/D04 **分别**标定固定的组内光心关系和朝向。`calibrate-intrinsics`、`calibrate-pose` 可生成所需文件，但须用独立点核验尺度与三维误差。单一已知长度不足以确定全部镜头参数。
2. 组内坐标可以各有水平原点。跨组测高时，两组都须以真实竖直向上为 `+Z`，并实测两组高度零点的差。误差文件需包含各点测高误差上界和高度基准误差上界；这些数字应来自不同位置、高度、距离的现场独立校验，不能用重投影像素误差直接冒充米制上界。
3. 安装和镜头参数不变时，组内标定以及高度偏移复用，不因人员、工件、车辆或普通背景变化而重做。相机松动、变焦、分辨率/裁剪改变，或不再满足纯水平平移时复标。每秒生成的 `height-state` 只是将离线组内几何绑定到本秒原图哈希，不是重新离线锚定。

## 组内自动测距

在 `Horizontal1` 目录运行：

```powershell
& 'D:\Anaconda\envs\crane-person\python.exe' -m pixel_distance video-distance `
  --time 2026-10-20T15:57:32 --reference D04 `
  --point-a 1000,500 --point-b 1100,600 `
  --videos-dir .. --out 'pixel_distance\demo_output\组内测距.json'
```

程序取四路各一帧，参考 A/B 向另外三路分别寻找视觉候选，再分别检查 D01/D03 和 D02/D04 两个固定组的三角几何。当前默认仍采用配置中的**名义**组内位置和方向，输出只能作为候选；有现场标定的本秒状态可加 `--pose-state`。若两点分属两组，还须加 `--height-alignment` 才可能输出高度差；无可靠同名点时 `distance_m=null`。旧的单目试算须显式加 `--assume-same-plane`，不能用于不同高度的点。

“建系”在这里是为两组各自建立固定的组内米制坐标，再离线对齐竖直方向及高度零点。它让小车水平位移不影响各组内部的距离与已对齐的跨组高度差，但不能从未知水平位置恢复跨组完整三维距离，也不能保证视觉模型匹配到任意选点。跨组两路候选都存在仍须通过目标组的正深度、交会角及重投影检查。

## 两组独立测高

`init-height-state` 接受四个 `image/pose` 配对。`image` 是本秒原图；`pose` 是离线组内标定的相机位姿文件，可在每秒重复使用。两组各自的水平原点不必相同，但其局部 `Z` 轴必须已对齐真实竖直方向。示意输入：

```json
{"views": [
  {"camera_id": "D01", "image": "E:/frames/D01.png", "pose": "E:/calibration/D01-pose.json"},
  {"camera_id": "D03", "image": "E:/frames/D03.png", "pose": "E:/calibration/D03-pose.json"},
  {"camera_id": "D02", "image": "E:/frames/D02.png", "pose": "E:/calibration/D02-pose.json"},
  {"camera_id": "D04", "image": "E:/frames/D04.png", "pose": "E:/calibration/D04-pose.json"}
]}
```

`compare-height` 接受两点各两路**同组同名像素**。A/B 可以来自不同组。`time` 只能精确到秒，示意输入：

```json
{"time": "2026-10-20T15:57:32",
 "A": [{"camera_id": "D01", "image": "E:/frames/D01.png", "pixel": [500, 400]},
       {"camera_id": "D03", "image": "E:/frames/D03.png", "pixel": [700, 430]}],
 "B": [{"camera_id": "D02", "image": "E:/frames/D02.png", "pixel": [800, 600]},
       {"camera_id": "D04", "image": "E:/frames/D04.png", "pixel": [900, 580]}]}
```

跨组高度基准文件由现场独立校验后提供。`validated` 是人工验收状态标记，程序只校验格式和数值，不会替你证明其真实性：

```json
{"status": "validated", "z_offsets_m": {"gantry": 0.0, "trolley": 0.0},
 "point_height_error_bound_m": {"A": 0.05, "B": 0.05},
 "alignment_error_bound_m": 0.03}
```

这里的 `z_offsets_m` 是“组内局部 Z 加多少米才等于共同离地高度”；`0.0` 只是格式示例，**不是本现场已校准的值**。误差区间采用保守上界之和；若没有可辩护的上界，不能把输出区间当成告警置信区间。

```powershell
& 'D:\Anaconda\envs\crane-person\python.exe' -m pixel_distance init-height-state `
  --views 'E:\inputs\本秒四路.json' --out 'E:\results\height-state.json'
& 'D:\Anaconda\envs\crane-person\python.exe' -m pixel_distance compare-height `
  --observations 'E:\inputs\两点同名像素.json' `
  --state 'E:\results\height-state.json' `
  --alignment 'E:\calibration\高度基准.json' `
  --out 'E:\results\高度比较.json'
```

示例路径和像素必须换成真实采集数据。`compare-height` 用图像哈希防止把某一秒状态套到另一张图，并检查同组关系、像素范围、正深度、交会角和重投影误差。`auto-3d` 与 `video-distance` 可从参考图自动寻找四路候选，并在输入经验证的位姿状态与高度基准时尝试跨组高度差。当前入口**尚未自动识别人员头顶或吊物真实最低点**；也未完成 B8 自动告警。完整三维距离以及 B6/B9/B10 的水平覆盖关系，不可由跨组高度差代替。
