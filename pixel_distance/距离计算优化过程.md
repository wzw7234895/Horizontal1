# 距离计算优化过程

更新时间：2026-11-08。

本文记录 `pixel_distance` 从最初的单相机像素估算，逐步扩展到多视角三维候选、视频自动取帧、跨视角匹配、地面候选分割和现场诊断的过程。文档同时说明每次优化解决了什么问题、没有解决什么问题，以及当前结果为什么可能返回 `unknown`。

## 1. 业务目标与基本约束

输入是在某一路相机原始全幅图像中选择的两个像素点 A、B，输出对应物理点的现实距离；如果两点不在同一高度，还希望输出高度差。选点不是固定的 A/B/C/D 标记，不能假设运行时总能看到运输车，也不能要求用户在其他视角手工重新指出同名点。

现场有 D01 至 D04 四路相机。D01/D03 属于行车侧人员相机，D02/D04 属于吊点侧相机。初期只有设计范围和名义值，没有完整的现场内参、畸变、帧级曝光时间及当帧跨组外参。因此代码必须区分三类结果：

1. **实测几何结果**：使用现场标定的内参、畸变、相对位姿、同步时间和可信同名点。
2. **名义条件结果**：使用 `camera_presets.json` 的假定参数，便于验证程序链路，但不能作为现场真值。
3. **无法确定**：匹配、几何或地面假设不成立时返回未知，避免用一个看似精确的数字掩盖深度缺失。

单个像素间隔不存在整幅图通用的米/像素比例。实际比例随深度、镜头畸变、相机俯仰和点所在平面改变；“固定参数加像素差”只能在已知平面或已知双目深度条件下成立。

## 2. 第一阶段：单相机名义地面估算

最初的 `estimate` 命令把相机看作针孔模型，依据图像宽度和水平视场角推算焦距，将像素反投影为相机射线，再与用户指定的水平面相交。默认水平面是 `Z=0` 地面，也可以通过 `--plane-height-m` 指定其他共同高度。

名义内参计算形式为：

```text
fx = fy = W / (2 * tan(horizontal_fov / 2))
cx = W / 2
cy = H / 2
```

世界射线为 `X(lambda) = C + lambda * R^T * K^-1 * [u, v, 1]^T`。两条射线与同一水平面相交后，计算两个平面点的欧氏距离。

这一阶段只能处理两个点确实位于同一个已知水平面上的情况。吊物最低点、人员头顶、工件边缘和车板边缘可能处于不同高度，直接投到地面会产生系统偏差；名义高度、视场角、俯角、主点和畸变也不能代替现场标定。因此输出状态使用 `nominal_estimate_not_calibrated`，并在 JSON 中记录实际采用的参数。

## 3. 第二阶段：任意高度的多视角三维交会

### 相机组坐标系

为支持悬空点，增加 `nominal_world_poses` 和固定相机组假设。每一路相机由光心、方位、俯角、滚转角和视场角生成一套相对坐标系。参考图中的像素点和辅助图中同名像素点分别形成空间射线，求两条射线的最近点作为三维候选。

对 A、B 分别三角化后计算：

```text
distance = ||X_B - X_A||
height_difference = Z_B - Z_A
```

高度差定义为 B 的世界坐标 Z 减 A 的世界坐标 Z，正值表示 B 高于 A。

### 几何检查

三维候选不会只由射线交会直接接受，而是检查极线误差、点是否位于各相机前方、交会角、视线最近距离、重投影误差和多视角一致性。`nominal-3d`、`manual-nominal-3d` 的 `max_ray_gap_m` 默认是 0.5 米。

这些检查只能验证“参数与候选之间是否自洽”，不能证明外参一定正确，也不能证明候选点确实是同一物理点。错误同名点也可能在错误参数下得到看似合理的交会，因此状态仍标记为 `nominal_3d_candidate_not_calibrated`。

当四路相机的相对位置和朝向固定，整组相机一起平移或旋转时，两点之间的相对距离不变，固定组内的相对三角几何可以复用。若相机组之间的相对位置改变，跨组三角化必须更新外参，或者先通过静态车间地图重新定位两组相机。仅有旧画面与新画面的重叠，不能为未知高度的新点自动补出深度。

## 4. 第三阶段：取消辅助视角手工点选

用户只在参考路选择 A、B。`auto-3d` 和 `video-distance` 会在其他视角中自动寻找候选点，当前匹配链路包括：

1. **SIFT**：轻量、无需训练，适合作为边缘盒默认方法。
2. **LoFTR**：预训练稠密匹配，适合纹理较弱或视角差较大的离线复核，但资源开销更高。
3. **XFeat**：预训练稀疏/半稠密特征，作为可选诊断方法，需要本地源码和权重。
4. **RoMa**：稠密跨视角候选，增加前向映射、反向回查和置信度检查，主要用于离线复核。
5. **Patch**：在已有可信双目位姿时进行立体校正，沿极线比较局部图像块；没有实测位姿时不能单独解决几何问题。

`auto` 可以让不同方法分别为 A、B 提供候选；同一点的候选如果相差超过 `MAX_MATCHER_DISAGREEMENT_PX=8` 像素，就拒绝该点。候选随后还要通过极线、三角化和重投影检查。

不直接接受视觉最高相似度，是因为跨视角图像包含时间字幕、边框、重复设备、吊物不同表面和地面。全图最高相似度可能来自字幕或重复结构，并不代表选定像素的物理点。没有局部支持、双向一致性、几何约束或重投影证据时返回 `unknown`，不强行输出高度差。

## 5. 第四阶段：场景上下文和局部投影

早期实现先按名义极线过滤特征，现场相机参数偏差较大时，真正候选可能在过滤范围外。优化后增加场景上下文路径：

- 先在整幅图建立特征对应；
- 在选点附近搜索能够覆盖其邻域的局部投影模型；
- 检查支持点数量、空间覆盖、局部残差和逆向映射；
- 形成候选像素后，再回到名义相机几何执行极线和三角重投影检查。

这减少了“因名义极线偏差过早丢弃候选”的问题，但不能解决另一视角不可见、无纹理、反光、遮挡、两路非同一曝光或相对位姿误差过大的情况。局部投影是扩大搜索范围的优化，不是深度真值来源。

## 6. 第五阶段：从图片扩展到四路视频

`video-distance` 根据视频文件名起始时间、帧率和 `video_clock_offset_s`，按用户给出的秒级时间分别抽取 D01 至 D04 的画面。参考路只需点击或提供 A/B 坐标，其余视角自动处理。

为减少工程噪声，目标帧在隔离解码进程中读取，H.264 的 `reference picture missing`、`mmco` 等重复警告不再刷屏；警告行数写入 `video_frames.*.decoder_warning_lines`，解码失败仍明确报错。结果 JSON 保存每路视频、帧号、帧率、文件起始时间和时间偏移。

秒级时间只能作为近似取帧依据，不能证明两路曝光同步。现场复核中，D04 同一烧录秒内静态背景的原图尺度中位位移约 34 像素，D03 约 0.1 像素，说明同一秒内相机运动也可能不同。正式三维测量仍需帧级或曝光级时间戳；第三码流片段可用于连续轨迹和遮挡复核，不能直接替代主码流像素坐标。

## 7. 第六阶段：运输车长度作为离线诊断

用户提供运输车前后总长约 4–5 米。程序增加车辆四标记、车板平面和已知长度检查，用于发现相机几何或局部尺度偏差。它可以提取车体红色端部标记、建立车板平面的条件映射、比较预测端点和人工点，并检查结果是否落在 4–5 米范围。

车长诊断不能把近似车长当成正式运行时的全局尺子，不能由一段长度唯一恢复两组相机完整的旋转、平移、焦距和畸变，也不能把车板平面映射推广到悬空工件、人员头顶或工件最低点。因此相关命令是 `vehicle-diagnostic`，输出带有 `diagnostic_only` 或 `approximate_vehicle_length_not_validated` 标记。运行时任意点仍需独立的多视角同名点和相机几何。

## 8. 第七阶段：地面候选分割门禁

为减少多视角失败后误用单目地面假设，增加 `ground_segmentation.py`，加载本地 SegFormer ADE20K，使用 `floor` 类别输出候选掩码。`segment-ground` 可生成绿色叠加图，并检查 A/B 的 `floor_probability`、`local_floor_fraction`、`model_label` 及 `ground_candidate_unverified`/`unknown` 状态。

启用 `video-distance --ground-model` 后：

1. 先尝试跨视角自动匹配和三角测量；
2. 多视角失败后，对参考图执行地面候选分割；
3. 只有 A、B 都通过概率和局部支持检查，才允许共同地面平面单目回退；
4. 否则返回 `distance_m=null`、`height_difference_m=null` 和 `unknown`。

该模型没有针对本车间和俯视相机训练。15:57:32 样例中，D01/D02/D03/D04 的候选像素占比约为 39.7%、0.0%、17.0% 和 2.9%；D01 存在车辆表面误分，D02/D04 的实际地面大面积漏分，D04 选点被判为 `wall`。地面分割目前只能作保守门禁和离线诊断，不能确认真实地面，更不能恢复悬空点深度。

## 10. 现场样例证据

针对 15:57:32 的 D04/D03 现场画面，先后检查了 SIFT、XFeat、LoFTR、RoMa、极线图像块和场景上下文：

- SIFT 在车长诊断位姿下有 13 组双向特征，但 0 组进入 3 像素极线阈值，最近极线误差约 33.1 像素。
- XFeat 增加了候选数，但 A/B 附近仍缺少同时满足局部几何和名义外参的点；8 像素网格查询的最高相似度约 0.701/0.727，反向查询不能回到原点附近。
- RoMa 能生成候选位置，但前后向回查误差和名义极线误差过大，候选被拒绝。
- 图像块匹配在合成双目数据上能够恢复选点和距离；现场诊断位姿将选点校正到有效图像区域之外，不能据此评价真实标定几何。
- 带地面分割门禁时，D04 A/B 被判为未知，程序不再输出有误导性的单目地面数值。

结论是：优化提高了候选搜索、错误拒绝、视频工程稳定性和结果可解释性，但没有替换现场内外参标定、同步和同名点可见性。当前现场样例不能报告经验证的真实三维距离或高度差。

## 11. 边缘盒部署优化

当前默认优先使用 SIFT，LoFTR、XFeat、RoMa 和 SegFormer 作为按需或离线方法。边缘盒芯片型号尚未确定，不能预先假设 RKNN、TensorRT 或其他转换链。建议按以下顺序压缩资源：

1. 仅在触发告警或用户请求时做跨视角匹配，不逐帧运行重模型。
2. 先在 640–960 像素宽缩略图上做全局候选，再回到原图做局部精修。
3. 缓存相邻帧特征和已验证的静态背景，只对移动区域重新匹配。
4. 固定相机组不变时缓存 `K/D/R/t`、极线映射和畸变校正表。
5. 地面分割只对告警点附近 ROI 推理，或替换为经过现场验证的轻量模型。
6. 统计每个模型的 CPU/NPU 耗时、峰值内存、帧率、候选召回率和误接受率，再决定是否转换为芯片专用格式。

## 12. 现场验收与后续优化顺序

正式输出米制距离前，建议按以下顺序验收：

1. 在最终安装、焦距、分辨率和裁剪状态下逐路标定内参和畸变。
2. 用同一米制坐标系的三维控制点标定固定组内外参；为跨组相机建立静态结构地图或可测位姿输入。
3. 记录实际曝光时间，验证视频码流、时间偏移和解码帧号的对应关系。
4. 在地面、车板、人员头顶高度、吊物不同高度分别布置独立校验点。
5. 用多个不同位置和距离的已知长度评估绝对误差、最大误差和不可判定率；车长只能作为其中一个独立检查项。
6. 采集现场地面、绿色轨道、黄色警戒线、车板和吊物区域的分割标注，评估地面候选误分和漏分。
7. 在目标边缘盒上测试 SIFT、轻量匹配网络和分割网络的资源占用，再确定实时频率和告警延迟。

验收报告必须同时记录成功和拒绝案例。`unknown` 不是程序故障，而是当前证据不足以支持三维距离或高度差的明确结论；只有通过独立控制点、重投影误差、同步和现场距离验证后，才可以把候选结果升级为正式测量结果。
