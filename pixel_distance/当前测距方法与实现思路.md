# 当前图像两点测距方法与实现思路

更新时间：2026-11-09。本文说明 `pixel_distance` 的测距链。**当前默认配置只允许 D01/D03 或 D02/D04 组内三维距离**；跨组水平相对位置不估计，两组分别测高后的比较见 [当前组内测距与跨组高度方案](当前组内测距与跨组高度方案.md)。旧四机固定试验结果仅作历史诊断。

## 一、输入与结果含义

用户在一路原始全幅画面中选取任意两个像素 A、B。它们可以在地面、车辆或不同高度的物体上，不预先固定为某四个标记点。程序计算的是对应物理点之间的直线距离 `||X_B-X_A||`；若三维点建立在同一个竖直向上的坐标系中，还可计算高度差 `Z_B-Z_A`。**像素间隔本身没有固定的米/像素比例**：深度、拍摄角度和镜头畸变都会改变局部尺度。

| 命令 | 主要方法 | 适用条件 | 结果性质 |
| --- | --- | --- | --- |
| `measure` | 像素到实测地面的单应映射；提供内参时先去畸变 | A、B 都在已标定地面 | 地面平面距离；取决于控制点和校验质量 |
| `estimate` | 名义针孔射线与指定水平面相交 | 已确认 A、B 位于同一已知高度水平面 | 未标定的条件估算 |
| `measure-3d` | 已标定相机位姿下的多视线交会 | 各视角同名点、相机位姿、曝光同步均有效 | 可检验的三维距离 |
| `auto-3d` | 四路视觉候选，固定组内双目三角测量 | A、B 各自在某一固定组的两路相机可见且匹配通过 | 名义或已标定组内三维候选；跨组可仅测高度 |
| `video-distance` | 同秒各抽一帧，向另三路找视觉候选，再按组内相机对测量 | 有四路视频及一路参考画面的 A、B | 组内三维候选、经标定的跨组高度差或未知；显式假定同平面时才可单目试算 |
| `init-height-state`、`compare-height` | 两组各自固定几何下独立测高，再按离线基准比较 Z | 各点有本组两路对应、竖直基准已验收 | 跨组只输出高度差与误差区间，不输出三维距离 |
| `segment-ground` | SegFormer ADE20K `floor` 像素分类 | 提供本地模型和原始全幅图 | 未经现场验证的地面候选掩码与选点诊断 |
| `nominal-3d`、`manual-nominal-3d` | 假定相机位姿与指定/手工同名点视线交会 | 两路 A、B 确认是同一物理点 | 离线条件试算，不是现场验收值 |

## 二、当前四路视频默认计算链

1. **同秒取帧。** `video-distance` 根据 `D01` 至 `D04` 视频文件名中的起始时间、视频帧率及配置中的 `video_clock_offset_s`，抽取目标时间对应帧。视频解码警告保留计数但不在终端刷屏。画面叠加的“同秒”时间并不证明真实曝光严格同步；移动目标仍可能有时间差。
2. **选择参考点。** 用户仅在 `--reference` 指定的一路点击 A、B，或给出原始分辨率下的 `--point-a x,y --point-b x,y`。缩放显示的点击会换回原始像素。其他三路不要求手工点同名点。
3. **建立组内相对坐标系。** 默认 `all_cameras_rigid=false`，仅 D01/D03 或 D02/D04 各自作为刚性组。程序用组内固定光心与朝向，以及各路视场角、俯角和滚转角建立相机几何；参数目前仍为**名义假设**，不是现场实测。不同组的水平原点不得直接相减。
4. **向全部辅助视角找对应点。** 参考组另一相机使用已有组内位姿的极线检查与局部视觉转移；跨组两相机使用 SIFT/LoFTR/XFeat 的图像特征与数据驱动的基础矩阵提出视觉候选，不使用未知的跨组固定外参。`--matcher patch/roma` 在跨组候选阶段回退 SIFT。候选只是像素位置，尚不是三维坐标；低纹理、遮挡或相似表面仍可能匹配失败。
5. **按固定组独立做几何检查。** D01/D03 和 D02/D04 分别用自己的固定组内米制位姿三角测量。要求同一点在该组两路都有候选，且正深度、交会角、重投影通过。参考图可以来自另一组，但不拿参考图与目标组单个镜头构成跨组米制基线。两组都能测得同一对点时，可对各自算出的距离做一致性检查；两组的水平坐标不可直接相减。
6. **给出结果或未知。** A、B 均在某一组完成双目定位时，输出组内三维候选距离和 `height_difference_m = Z_B-Z_A`。若 A、B 分别只在不同组完成双目定位，须提供现场标定的本秒位姿状态及经验证的竖直高度基准，才输出高度差与误差区间，`distance_m=null`。其他失败默认未知。只有显式 `--assume-same-plane` 才允许原单目试算；`--ground-model` 仅用于该试算的地面候选门禁。

流程可概括为：

```text
同秒四路视频帧 + 参考路 A/B
            |
     四路跨视角视觉候选
            |
     两组各自固定的米制位姿
            |
    各组双目正深度、交会角、重投影检查
        /                       \
  A/B 同组通过              未通过
        |                       |
 三维距离与高度差           跨组经验证时仅高度差；否则未知
```

核心数学关系如下。对图像宽度 `W` 和水平视场角 `alpha`，当前名义内参采用 `fx=fy=W/(2 tan(alpha/2))`、主点为图像中心，畸变系数暂置零。像素 `p=(u,v,1)` 去内参后的方向是 `K^-1 p`；相机中心 `C` 和旋转 `R` 将其变为世界射线 `X(lambda)=C+lambda R^T K^-1 p`。两路相机的对应射线交会确定一个三维点；对 A、B 分别求得 `X_A`、`X_B`，再计算欧氏距离。极线约束为 `p_2^T F p_1≈0`。这些方程能检查给定参数和候选的内部一致性，**不能从错误的外参或错误的同名点自动得到真实距离**。

## 三、其他已经实现的测距路径

**地面标定映射。** `calibrate-intrinsics` 用棋盘格估计真实内参和畸变；`calibrate-plane` 用同一地面上的实测米制控制点拟合像素到地面坐标的单应矩阵，并用独立检查点验收。`measure --surface ground` 在标定文件提供内参时先对 A、B 去畸变，然后做单应变换并求地面二维距离；无内参时直接使用原始像素，广角边缘误差可能更大。该矩阵只对所标定的平面成立；人员头顶、吊物底部和车板等其他高度不能直接使用。相机相对地面移动后，也不能无条件复用旧地面映射。

**实测位姿三角测量。** `calibrate-pose` 通过实测三维控制点和相机内参求每路位姿；`init-height-state` 把两组独立标定的固定几何绑定到本秒画面，`compare-height` 分别测高后只在竖直方向对齐。`measure-3d`、`auto-3d --pose-state` 可用已知同名点或自动候选测量同组点。`video-distance` 也可接收 `--pose-state` 和 `--height-alignment`，但状态必须绑定本次抽出的原图哈希；未提供时默认采用未验收的名义组内几何。`track-pose` 是历史短程位姿更新路径，会累计漂移，不是当前方案的跨组运动估计。

**车板和已知长度诊断。** `vehicle-diagnostic` 可在特定画面中检测运输车四个端部标记，拟合车板平面映射，并用假定车长检查局部几何。`reference-check` 也可用其他独立已知长度检查偏差。这些是离线诊断，运行时任意点测距不以车长为尺度输入；车板单应映射仅限同一车板平面，不能推广到悬空工件或人员。

## 四、当前参数与可报告结论

当前默认配置见 [camera_presets.json](camera_presets.json)：D01/D03 水平视场角 `60°`、俯角 `45°`；D02/D04 水平视场角 `80°`、俯角 `85°`；四路名义高度均为 `10 m`。组内光心位置在 `center_in_rig_m`，D01-D03 名义基线为 `10 m`、D02-D04 为 `2 m`。`epipolar_candidate_threshold_px=20` 只是候选筛选门槛，**不是测距误差上界**。设计范围、名义值和旧四机共同光心参数均不能代替现场实测标定。

截至本次现场画面复核，D04 选点在 D01/D02/D03 均未同时通过视觉与名义几何检查；D03 的视觉候选虽接近人工标出的近似区域，仍未通过极线及三角重投影验证。因此对该样例，程序没有获得经确认的真实三维距离或高度差。**当前能运行并输出数字，不等于已达到现场测量精度。**正式报告米制三维结果前，需在最终安装、焦距、分辨率和裁剪状态下测得每路 `K/D`、相机间 `R/t`，检查帧同步和同名点，再用独立的不同位置、高度点验证误差。详见 [README.md](README.md) 的现场复核记录。

新增场景上下文与跨方法合并后，15:57:32 的四路原帧仍缺少足够的车板局部跨视角特征，不能生成经几何确认的 A/B。完整视频命令的[复核结果](demo_output/video_distance_场景上下文复核_155732.json)仍为 `single_view_assumed_plane_estimate`：约 `4.124 m`，仅在两点都位于地面这一假设下成立，真实高度差未知。新增方法适用于其他有局部纹理、又被错误名义极线过早过滤的场景，但**没有证明本例已经实现三维测距**。

新增的[地面分割](ground_segmentation.py)仅输出 `floor` 候选概率及叠加图。只有显式 `--assume-same-plane --ground-model` 才将它用于单目地面试算门禁。旧[现场叠加图](demo_output/ground_segmentation)显示 D01 有车辆误分、D02/D04 有地面漏分，因此不能把候选当成地面真值或悬空点深度；该模型仍须用现场标注验证或替换。

## 五、运行示例

在项目根目录，使用已有 `crane-person` 环境：

```powershell
& 'D:\Anaconda\envs\crane-person\python.exe' -m pixel_distance video-distance `
  --time '2026-10-20T15:57:32' --reference D04 `
  --point-a 1278.17,445.71 --point-b 1254.86,922.97 `
  --out 'pixel_distance\demo_output\本次测距.json'
```

要启用地面分割门禁，在该命令后另加 `--ground-model 'D:\w\codex-conversations\2026-11-07\crane-ground-segmentation\segformer-b0-ade20k'`；`segment-ground` 的独立叠加图命令和环境要求见 [README.md](README.md)。

省略 `--point-a/--point-b` 时在 D04 抽帧画面点击。详细结果保存在 JSON 的 `measurement_mode`、`views`、`distance_m`、`height_difference_m` 和相关状态字段中；终端默认只显示简短中文结果。该示例中的 A/B 只是一次选点，不是程序内置的固定测量目标。
