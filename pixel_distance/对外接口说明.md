# 距离计算程序对外接口说明

更新时间：2026-11-10。当前提供 Python 进程内接口和 HTTP/JSON 接口，两者共用同一套 `pixel_distance` 计算逻辑。

## 测量约定

- 调用方在参考相机画面选择 A、B；四路图像都必须是同一业务秒抽取的原始全幅帧，分辨率、裁剪和配置中的相机内参必须一致。
- 当前每次测量提交 D01、D02、D03、D04 四路 BGR 图像。服务自动向另外三路寻找 A/B 候选。候选只用于视觉对应；米制三角测量只使用固定组内 D01/D03 或 D02/D04 的几何。
- 同组双目可输出距离候选。若 A、B 分别只在不同组完成定位，需同时提供与本次图像哈希相符的现场位姿状态及已验证的竖直高度基准；这种情况只返回高度差，`distance_m` 为 `null`。
- 相机预设当前含名义值。`distance_available=true` 表示程序计算出了一个数；`distance_determined=true` 才表示底层算法明确给出现场确认结果。名义估值通常前者为真、后者为假。对外告警逻辑应结合 `status`、`measurement_mode` 和标定状态，不能只检查距离非空。
- 四路图像应来自目标秒抽帧；API 不从视频中自行选帧，也不校正不同码流延迟。使用本程序的视频时钟偏移配置时，可由上游按该秒抽帧后提交。

## Python 接口

此方式适合距离算法与边缘盒推理程序运行在同一个 Python 进程。输入图像必须是 OpenCV 解码后的 `uint8`、BGR、`H×W×3` NumPy 数组；A、B 坐标使用参考图的原始像素坐标。

```python
from pixel_distance.service import DistanceService

service = DistanceService("pixel_distance/camera_presets.json")
result = service.measure_images(
    images={"D01": frame_d01, "D02": frame_d02,
            "D03": frame_d03, "D04": frame_d04},
    reference_camera="D04",
    point_a=[1278.2, 445.7],
    point_b=[1254.9, 923.0],
    timestamp="2026-11-10T12:34:56",
    matcher="sift",
)
print(result["distance_m"], result["status"])
```

方法参数：

| 名称 | 类型 | 含义 |
| --- | --- | --- |
| `images` | `dict[str, np.ndarray]` | D01 至 D04 的同秒 BGR 原始全幅帧 |
| `reference_camera` | `str` | A/B 像素所属相机，如 `D04` |
| `point_a`, `point_b` | `[x, y]` | 参考帧中的像素坐标，原图像素单位 |
| `timestamp` | ISO 秒级字符串或 `None` | 本次抽帧时间，格式 `YYYY-MM-DDTHH:MM:SS` |
| `matcher` | `auto/sift/loftr/xfeat` | 跨视角候选算法；边缘端可用 `sift` 限制推理资源 |
| `pose_state` | JSON 对象或 `None` | 可选的本秒组内相机标定位姿，图像哈希须一致 |
| `height_alignment` | JSON 对象或 `None` | 可选的离线验证竖直高度基准，仅用于跨组高度差 |

启动时可传入自定义完整相机配置，也可通过 `service.update_config(config)` 更新当前进程的配置。更新要求四台相机、两个各含两台相机的固定组，并强制 `all_cameras_rigid=false`，防止误用跨组固定基线。配置更新只在当前进程内有效，生产部署应将确认后的数值写入配置文件并重启加载。`get_camera_info()` 返回相机名称、组别、名义高度/视场/角度和标定状态。

## HTTP 接口

安装可选 API 依赖：

```powershell
& 'D:\Anaconda\envs\crane-person\python.exe' -m pip install -r pixel_distance\requirements-api.txt
```

在项目根目录启动服务：

```powershell
$env:PIXEL_DISTANCE_CONFIG = 'E:\横向项目-目标检测\pixel_distance\camera_presets.json'
$env:PIXEL_DISTANCE_HOST = '0.0.0.0'
$env:PIXEL_DISTANCE_PORT = '8000'
& 'D:\Anaconda\envs\crane-person\python.exe' -m pixel_distance.api_server
```

服务启动后，`http://127.0.0.1:8000/docs` 提供交互式 OpenAPI 文档。支持的路由如下：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/health` | 服务存活检查 |
| `GET` | `/v1/cameras` | 获取相机组、名义参数、时钟偏移及配置版本 |
| `PUT` | `/v1/config` | 替换当前进程相机配置；请求体为完整 JSON 配置 |
| `POST` | `/v1/measure/images` | 上传四路图像和参考帧 A/B 像素并执行测量 |

`POST /v1/measure/images` 使用 `multipart/form-data`。必需文件字段为 `D01`、`D02`、`D03`、`D04`，各文件上限 20 MiB，支持 OpenCV 可解码的 PNG/JPEG 等格式。必需文本字段：`reference_camera`、`point_a_x`、`point_a_y`、`point_b_x`、`point_b_y`；可选字段：`timestamp`、`matcher`、`pose_state_json`、`height_alignment_json`。坐标以参考图原始分辨率为准。姿态和高度基准字段若提供，值为 JSON 对象序列化后的文本。

调用示例：

```powershell
curl.exe -X POST 'http://127.0.0.1:8000/v1/measure/images' `
  -F 'reference_camera=D04' `
  -F 'point_a_x=1278.2' -F 'point_a_y=445.7' `
  -F 'point_b_x=1254.9' -F 'point_b_y=923.0' `
  -F 'timestamp=2026-11-10T12:34:56' -F 'matcher=sift' `
  -F 'D01=@D01.png' -F 'D02=@D02.png' `
  -F 'D03=@D03.png' -F 'D04=@D04.png'
```

## 返回格式

HTTP 和 Python 返回相同结构。典型字段如下：

```json
{
  "schema_version": "1.0",
  "request_id": "每次请求生成的 UUID",
  "timestamp": "2026-11-10T12:34:56",
  "status": "nominal_3d_candidate_not_calibrated",
  "measurement_mode": "same_group_nominal_3d",
  "reference_camera": "D04",
  "points_px": {"A": [1278.2, 445.7], "B": [1254.9, 923.0]},
  "distance_m": 3.21,
  "distance_available": true,
  "distance_determined": false,
  "height_difference_m": 0.42,
  "height_difference_definition": "Z_B - Z_A",
  "height_difference_available": true,
  "height_difference_determined": false,
  "metric_group": "trolley",
  "point_support": {"A": ["D02", "D04"], "B": ["D02", "D04"]},
  "views": {},
  "reason": null,
  "config_revision": "配置内容 SHA-256 前 16 位"
}
```

关键结果：

- `status=unknown`：不能给出可靠的组内三维距离；`distance_m=null`。查看 `reason`、`views` 下各路匹配状态。
- `measurement_mode=same_group_nominal_3d`：使用当前名义参数得到组内三维候选，数值未现场标定验收。
- `measurement_mode=same_group_3d`：使用输入的现场位姿状态得到组内距离；仍按底层状态说明检查精度验收状态。
- `measurement_mode=cross_group_height_only`：仅给跨组高度差和 `height_difference_interval_m`，完整距离一定为 `null`。
- `distance_available` 与 `distance_determined` 有意区分“算出候选数值”和“现场已确认”。同理高度字段也分为 `height_difference_available` 与 `height_difference_determined`。
- `views` 为 D01-D03（参考为 D04 时）各辅助视角的候选及诊断；`pixel_points` 中 `null` 表示该点在该视角未匹配。视觉候选不是已确认的物理点。

输入格式、相机参数或坐标无效返回 HTTP `422`；单纯视觉匹配失败属于有效测量请求，HTTP 仍返回 `200`，由 `status=unknown` 表示算法无法判定。

## 配置与部署

`GET /v1/cameras` 可查询名义参数。通过 `PUT /v1/config` 更新时传入整个 `camera_presets.json` 对象，而不是局部 patch。例如可以调整 `cameras.D04.height_m`、`horizontal_fov_deg`、`down_tilt_deg`、`center_in_rig_m` 和 `video_clock_offset_s`。更新前应先保存确认后的配置副本；HTTP 更新不写磁盘，服务重启后回到 `PIXEL_DISTANCE_CONFIG` 指定文件。

该 HTTP 服务当前没有身份认证或 TLS，建议仅绑定车载盒可信内网，或由现场已有网关提供访问控制和 HTTPS。四张图像会在请求处理后释放；程序不保存图像。可结合 `request_id`、`timestamp` 与 `config_revision` 记录调用链。正式接入前还应在边缘盒实际测试四路图像上传/解码、候选匹配耗时和内存占用。
