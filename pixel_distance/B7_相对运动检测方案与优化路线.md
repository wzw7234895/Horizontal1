# B7 大车与小车相对运动检测方案

本文对应[设计说明](../../检测能力体系详细设计说明（内部参考版）%20(2).docx)中的 **B7：已装载吊物时，大车与小车同时运行检测**。设计说明还要求通过视觉估计相机自运动（C04），且不接入起重机电气信号或其他传感器。本文说明当前代码如何实现这一目标、什么情况下不能判定，以及现场部署前应如何优化和验收。B7 只判断运动状态；本轮暂不把小车位移写回两点测距的相机位姿。

## 1. 观测对象与判定定义

按当前视频及配置，D01/D03 是固定在大车端梁上的行车相机，D02/D04 是固定在小车上的警戒相机。两台行车相机一起随大车移动；两台警戒相机既随大车移动，也随小车相对大车移动。四路相机对同一静止车间背景的表观运动，是估计各自机架运动的依据。

设相邻帧时间差为 `dt`，四台相机从背景估计的水平速度向量分别为 `v01`、`v02`、`v03`、`v04`。在两组各自通过一致性检查后，计算：

```text
v_gantry        = (v01 + v03) / 2
v_trolley_total = (v02 + v04) / 2
v_trolley_rel   = v_trolley_total - v_gantry
s_gantry        = dot(v_gantry, gantry_axis)
s_trolley       = dot(v_trolley_rel, trolley_axis)
```

因此，**小车组相对大车组发生位移本身不足以触发 B7**；还必须同时确认大车沿自身运行轴移动。若四台相机一起移动，而小车不相对大车移动，则 `v_trolley_rel` 应接近零。若只有小车运行，则 `s_gantry` 应接近零。`gantry_axis` 与 `trolley_axis` 是配置中的两个近似正交单位向量；当前名义值分别为 Y 轴和 X 轴，仅适用于当前试运行坐标约定，不是现场实测轨道方向。

这里的“同方向持续”指**大车在自身轴上的速度符号保持不变，小车在自身轴上的速度符号也保持不变**；两者沿不同轨道轴，不要求两个二维速度向量平行。

## 2. 当前实现的处理流程

1. 外部挂载模块传入 `loaded=True` 才开始分析；`False` 或 `None` 不触发 B7，并清空运动历史。程序不自行识别吊物是否挂载。
2. 每次输入同一时刻的 D01 至 D04 四路 BGR 原始帧及递增的秒时间戳。离线命令以指定时刻为中心读取前后各 3 秒，默认每 0.2 秒取一组；实时接口只保存上一组原始帧副本和最近 6 秒的区间摘要。
3. 单路运动估计先把画面缩至最大边 960 像素，在亮度适中的区域提取最多 1200 个角点，排除画面顶部约 12% 和底部约 8%。可以额外传入每路静态地面候选掩码；**未传掩码时，亮度和画面位置筛选并不等于真正的地面分割**。
4. 对角点做金字塔 Lucas-Kanade 正反向光流；用名义相机内外参将匹配像素射线投到 `Z=0` 水平地面，拟合 RANSAC 二维相似变换，再由背景反向位移估计相机运动。这里假设被采用的背景点是静止、近似共面的地面点；运动中的车板、吊物、行人或高出地面的结构会破坏该假设。
5. 每路估计须通过双向光流、几何内点数量及比例、空间覆盖、短时旋转/尺度变化和残差检查；否则该区间为 `unknown`。然后分别检查 D01/D03 与 D02/D04 的速度向量是否一致，才计算两组平均速度和小车相对速度。
6. 两轴投影速度的绝对值均达到门槛，且非目标轴残差不过大时，该区间标记为双轴同时运动。只有这些区间**相邻、无断档、两个轴各自的速度符号不变，累计至少 3 秒**，才返回 `alarm_candidate`。未知区间、停顿或任一轴反向都会中断这段连续时长。

核心实现位于 [`b7_motion.py`](b7_motion.py) 的 `estimate_camera_motion`、`B7MotionDetector.update` 和 `result`；命令行入口位于 [`cli.py`](cli.py)，相机名义参数和运行轴在 [`camera_presets.json`](camera_presets.json)。算法不调用跨视角同名点匹配、三角测量或深度学习模型，也不依赖车长等运行时尺度锚。

## 3. 当前阈值与输出含义

| 参数或检查 | 当前默认值 | 含义 |
| --- | ---: | --- |
| 采样间隔 | 0.2 秒 | 离线命令的四路采样间隔；实时接口要求相邻有效帧不超过 0.5 秒。 |
| 时间窗 | 6 秒 | 离线查看中心时刻前后各 3 秒；实时只保留最近 6 秒摘要。 |
| 连续双轴运动 | 3 秒 | 满足条件的相邻区间累计时长，非任意零散区间的总和。 |
| `min_speed_mps` | 0.08 米/秒 | 大车轴速度和小车相对大车的轴速度均需达到此值。 |
| `max_group_disagreement_mps` | 0.12 米/秒 | `norm(v01-v03)` 和 `norm(v02-v04)` 各自不得超过此值；当前也用作非目标轴速度残差上限。 |
| RANSAC 支持 | 至少 45 个内点、比例至少 55% | 还要求内点凸包覆盖画面至少 4%；这些阈值只衡量模型一致性，不证明点真在地面。 |
| 短时模型检查 | 旋转不超过 3 度，尺度偏离 1 不超过 4% | 内点残差中位数不超过 0.06 米、90 分位不超过 0.15 米。 |

组内“不一致”比较的是**两台相机估计的二维速度向量差的欧氏长度**，不是原始像素差。按默认 0.2 秒间隔，0.12 米/秒相当于该间隔内约 2.4 厘米的**名义投影位移差**，并非现场已证实的测量精度或容许安装形变。阈值目前是试运行设置，应与标定误差、真实运行速度和误报/漏报成本一起调整，不应单独放宽以追求更多告警。

输出 `alarm_candidate` 表示已挂载且视觉运动证据达到当前门槛；`no_simultaneous_motion` 表示窗口内未出现连续 3 秒的双轴运动且所检查区间均可分析；`unknown` 表示存在无法可靠分析的区间且未形成候选告警，**不能解释为设备静止或 B7 不存在**。`not_loaded` 和 `unknown_load_state` 分别表示外部明确未挂载和挂载状态未知。完整 JSON 的 `intervals` 保留每路位移、组内差异、分解速度和拒绝原因；`distance_geometry_updated=false` 表示没有修改测距位姿。当前候选告警基于名义相机几何，尚未取得现场业务验收精度。

## 4. 现场样例与边界条件

在现有四路视频的 `2026-10-20T15:57:32` 附近，按默认 0.2 秒抽取前后各 3 秒，共形成 30 个相邻区间。本地诊断文件 `pixel_distance/demo_output/b7_window_3s_155732.json` 的结果为 `unknown`，`b7_alarm=false`：16 个区间通过单区间分析，14 个因组内运动不一致被拒绝；其中 D01/D03 超过 0.12 米/秒 4 次，D02/D04 超过门槛 11 次，有 1 次两组同时超限。没有区间形成有效的双轴同时运动证据，因此不能凭该样例判断现场是否发生过 B7。该 JSON 被 Git 忽略，其他设备上可用第 6 节命令重新生成诊断结果。

以下情况会导致 `unknown`、误估或需要额外处理：

- 四路视频的时间戳或 `video_clock_offset_s` 不准，尤其在启动、停止或反向时；四路虽然同秒，却可能对应不同运动阶段。实时四路输入应记录采集时间而非仅用处理完成时间。
- 背景角点被吊物、运输车、行人、移动阴影、屏幕叠加层或反光占据；RANSAC 能拒绝部分离群点，但当错误表面占多数时也可能拟合出自洽的假运动。可选的静态掩码需要与真实相机画面、裁剪和机位保持一致。
- 名义焦距、畸变、俯角、朝向、高度或地面高度不符合安装实际；把非地面特征投向 `Z=0` 会使不同视角的米制速度不一致。当前 `b7_axes` 只是一组试运行方向。
- 镜头变焦/自动电子防抖、相机支架振动或旋转、运动模糊、压缩损伤、低照度和地面无纹理；当前仅容许小幅旋转与尺度变化，超过检查限度就拒绝该区间。
- 采样丢帧超过 0.5 秒、任一路画面缺失或尺寸变化。当前 API 要求每组四路齐全；离线命令缺帧会报错，实时接口不能自动从两路退化判定。时间窗里的短暂未知区间会打断连续 3 秒确认。
- 相机与其所在机架之间并非刚性固定，或 D01/D03、D02/D04 的物理分组与实际安装不符。此时组内一致性前提不成立，不能通过调大阈值掩盖。

设计说明的 B7 是业务目标，不提供上述阈值或现场真值。[《解决方案》](../../解决方案.docx)在测距示例中使用 `slider_x`、`rail_y` 等外部机械位置输入；本项目 B7 按“不接起重机电气信号”的设计约束，以视觉背景运动估计替代该输入。视觉估计可在条件合适时判断运动，但不能直接证明毫米级位移或恢复测距所需的完整跨组相对位姿。

## 5. 优化与验收路线

1. **建立可核对的现场数据**：在大车单独运行、小车单独运行、两者同时运行、两者停止、反向、吊物遮挡、车板移动和夜间/反光等状态下，采集四路原始帧及采集时刻；由现场人员标注挂载状态和实际运动区间。先统计 `unknown` 原因、组内速度差、候选告警的延迟和误报/漏报，再调整阈值。
2. **校准时间与几何**：逐路核对视频时间偏移、帧率和解码定位；在最终安装、变焦、分辨率下测量内参、畸变、俯角、高度与运行轴方向。用多处静止地面控制点及独立运动片段检查每路速度方向、比例和组内差值；不能只以车长或单段视频反推整组参数。
3. **提高背景可信度**：先用固定静止区域/人工标注掩码排除吊物、运输车、人员和叠加层；再评估逐帧轻量语义分割或目标检测掩码是否能降低错误特征占比。按网格分散选点，检查多个区域的运动是否一致；同时保留被拒绝区间及可视化光流供诊断。地面分割模型必须在本车间画面上验证，不能把通用模型预测直接当作地面真值。
4. **增加短窗稳健性**：对有效区间的轴向速度做稳健时间聚合，并区分短时遮挡与真实停顿；任何允许跨越未知区间的规则都要单独验证，不能悄悄把零散位移拼成 3 秒。可考虑对四路观测做联合估计，显式建模支架微振动和每路观测不确定性，再由独立样例确定组内一致性阈值。
5. **适配边缘盒**：实时路径保持四路连续解码和帧缓存，避免离线命令每个时间点重新开四个解码进程；按需要降低采样率、分辨率和角点上限，并对 CPU、内存、视频解码与其他检测任务共存时的端到端延迟做实测。当前算法主体是 OpenCV 光流和 RANSAC，不能把设备 NPU 标称 TOPS 当作其运行性能保证。
6. **形成上线门槛**：用独立日期、不同机位/光照和不同运行速度的视频验证 B7 检出率、误报率、未知率及告警延迟；冻结参数后再回放盲测。若无法在可接受的未知率下实现稳定视觉判断，应明确业务降级方案或重新讨论是否允许接入可验证的机械位置/运动信号。

## 6. 使用入口

在 `Horizontal1` 目录运行，四路视频位于父目录时：

```powershell
& 'D:\Anaconda\envs\crane-person\python.exe' -m pixel_distance b7-motion `
  --time 2026-10-20T15:57:32 --videos-dir .. `
  --load-state confirmed `
  --out 'pixel_distance\demo_output\b7_155732.json'
```

实时系统调用 `B7MotionDetector(config).update(timestamp_s, images, loaded)`；`images` 必须包含 D01、D02、D03、D04 同一采集时刻的 BGR 帧。参数含义和简单调用示例见 [`README.md`](README.md#b7挂载重物时大车和小车同步运行)。上述命令中的 `confirmed` 仅用于演示调用接口，不能代替真实挂载判定。
