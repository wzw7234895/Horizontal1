# 人员检测程序对外接口说明

本文定义人员检测与持续跟踪程序供其他程序调用的接口。当前提供两种入口：命令行进程接口，以及 Python 进程内 SDK。Python SDK 可在每个分析帧完成时同步回调结构化结果；相机视频或 RTSP 地址通过配置文件传入。当前没有单独的 HTTP/gRPC 服务端点。

## 1. 输入接口

相机配置沿用 `configs/cameras.json`。每个相机至少包含唯一 `id` 和 `source`；`source` 可以是本地视频路径，也可以是 RTSP URL。可选字段 `name`、`mount`、`recording_start`、`time_offset_s` 和 `roi` 用于标识、录像时间估计和 ROI 状态标注。ROI 使用 0 到 1 之间的归一化多边形坐标；它只产生 `inside_roi` 状态，不裁掉 ROI 外检测。Python SDK 也可通过 `roi_overrides` 在单次运行时按相机传入或覆盖多边形；未指定的相机沿用配置文件 ROI。

生产运行应显式指定训练权重。`device` 支持 `auto`、`cpu` 或 CUDA 设备编号，例如 `0`；`image_size` 是模型输入尺寸；`analysis_fps` 是抽帧处理目标，不改变源视频帧率。

## 2. Python SDK

从项目根目录运行，使用 `crane-person` 环境，并确保配置中的模型、跟踪器和输入源路径可读：

```python
from person_tracking.api import run_person_tracking
from queue import SimpleQueue
from threading import Event

publish_queue = SimpleQueue()
stop_event = Event()

def on_frame(record: dict) -> None:
    for person in record["detections"]:
        if person["observed"] and person["track_id"] is not None:
            # 将真实观测放入业务队列；不要在回调中执行阻塞网络请求。
            publish_queue.put({
                "camera_id": record["camera_id"],
                "session_id": record["session_id"],
                "track_id": person["track_id"],
                "bbox_xyxy": person["xyxy"],
                "timestamp_s": record["video_time_s"],
            })


result = run_person_tracking(
    config="person_tracking/configs/cameras.json",
    camera_ids=["D02"],
    weights="person_tracking/runs/train/person_yolo11n_static_v13_hard_merged_20261108_r2/weights/best.pt",
    device="0",
    image_size=1280,
    analysis_fps=10,
    output_dir="person_tracking/runs/api_d02",
    save_video=False,
    roi_overrides={"D02": [[0.1, 0.2], [0.9, 0.2], [0.95, 0.9], [0.05, 0.9]]},
    on_frame=on_frame,
    stop_event=stop_event,
)
print(result["status"])
```

函数签名：

```python
run_person_tracking(
    *, output_dir, config=DEFAULT_CONFIG, camera_ids=None, weights=None,
    device=None, image_size=None, analysis_fps=None,
    start_seconds=0.0, duration_seconds=None, max_frames=None,
    save_video=True, preview_width=1280, decode_mode="sequential",
    frame_enricher=None, roi_overrides=None, on_frame=None, stop_event=None,
) -> dict
```

`output_dir` 必须是尚不存在的新目录。`camera_ids=None` 表示使用配置中的全部相机；也可以传单个字符串或字符串列表。`roi_overrides` 是 `{camera_id: [[x1,y1], ...]}` 映射，坐标均为 `[0,1]` 归一化值，至少三个点；仅覆盖本次选中的相机，名称错误或坐标越界会报错。ROI 只计算人员框底中心的 `inside_roi`，不裁掉 ROI 外的全图检测。`frame_enricher(frame, record)` 在每个分析帧同步收到原始 BGR 帧和人员记录，可就地绘制或给记录添加属性，并返回更新后的记录；返回 `None` 表示保留原记录。它在持久化帧记录和 `on_frame(record)` 回调之前运行。`on_frame(record)` 在检测、跟踪、增强及可选回放写入之后同步调用一次。回调异常会中止该次运行并向调用方传播；RTSP 解码只保留最新帧，慢回调会使后续帧被跳过，因此回调应快速写入线程安全队列。持续运行的 RTSP 可由其他线程调用 `stop_event.set()` 请求正常停止，函数返回 `status="stopped"` 并写入最终摘要。普通完成返回 `status="completed"`，Ctrl+C 返回 `status="interrupted"`。路径、配置或参数错误以 Python 异常报告。

## 3. 单帧结果结构

SDK 回调对象和 `frames.jsonl` 使用同一 JSON 记录，`schema_version` 当前为 `"1.0"`：

```json
{
  "schema_version": "1.0",
  "camera_id": "D02",
  "session_id": "run-id-D02-1",
  "analysis_frame": 12,
  "source_frame": 275,
  "video_time_s": 11.0,
  "source_fps": 25.0,
  "time_basis": "file_pts",
  "source_frame_basis": "decoded_frame_count",
  "recording_time_estimate": "2026-10-20T15:21:44",
  "width": 1920,
  "height": 1080,
  "detections": [
    {
      "class_id": 0,
      "label": "person",
      "confidence": 0.94,
      "xyxy": [410.0, 220.0, 520.0, 640.0],
      "bbox_bottom_center": [465.0, 640.0],
      "track_id": 3,
      "observed": true,
      "predicted": false,
      "prediction_age_s": 0.0,
      "track_confirmed": true,
      "displayed": true,
      "inside_roi": null
    }
  ],
  "raw_detection_count": 1,
  "detections_suppressed_nested": 0
}
```

坐标约定：`xyxy=[x1,y1,x2,y2]` 和 `bbox_bottom_center=[x,y]` 均以该记录的 `width`、`height` 为基准，单位为输入帧像素；不是预览视频或模型缩放后的坐标。边界框右下坐标按 OpenCV/YOLO 浮点坐标表示。

`observed=true` 表示该帧有检测器输出的真实人员候选，`predicted=true` 表示遮挡期间按短时运动外推的显示框。真实检测框可能尚未关联到已确认 ID，此时 `track_id=null`；确认后，人员键应使用 `(camera_id, session_id, track_id)`。预测记录会沿用最近一次置信度并携带 `prediction_age_s`，不能当作当前帧检测结果或真实位置。当前最多显示 2 秒预测框，轨迹在无观测 2.5 秒后关闭；两项由配置控制。

`inside_roi=null` 表示未配置 ROI。`displayed` 与 `display_xyxy` 描述绘制状态；业务事件判断应基于 `observed`、`track_id` 和原始 `xyxy`，不要把显示平滑框当作检测器原始框。`track_candidate_id` 是跟踪器内部候选标识，仅供诊断；集成系统不得将其作为长期人员 ID。

需要添加安全帽或工装属性时，可将 `person_tracking.b3b4.create_analyzer()` 返回的 callable 传给 `frame_enricher`。B3/B4 行为、输出字段与告警门控见[专项方案](B3B4安全帽与工装颜色专项方案.md)。

本地视频 `time_basis="file_pts"` 时，`video_time_s` 是容器呈现时间戳，`recording_time_estimate` 根据配置文件名时钟估算。RTSP 使用 `time_basis="host_arrival"`，时间相对本进程启动，不是相机曝光时间。`source_frame` 是从 0 开始的源解码帧序号；`analysis_frame` 是从 1 开始的抽样分析序号。两者不能混作同一帧号。

## 4. 命令行与文件接口

PowerShell 可通过现有脚本启动同一程序：

```powershell
.\person_tracking\run.ps1 track `
  --config person_tracking/configs/cameras.json `
  --cameras D02 `
  --weights person_tracking/runs/train/person_yolo11n_static_v13_hard_merged_20261108_r2/weights/best.pt `
  --device 0 --imgsz 1280 --fps 10 --no-video `
  --out person_tracking/runs/api_d02
```

完成后可读取 `summary.json`，逐帧记录读取 `D02/frames.jsonl`，轨迹汇总读取 `D02/tracks.jsonl`。JSONL 每行都是独立 JSON 对象，适合按行解析；进程运行时文件会持续追加，消费者应容忍最后一行尚未写完并在关闭后重试解析。

## 5. ID、实时性与业务约束

每个相机使用独立跟踪器；不同相机相同数字的 `track_id` 不代表同一人。RTSP 重连会创建新的 `session_id`，ID 不跨相机、进程运行或 session 保证连续。程序目标分析率默认 10 fps；直播读取器采用最新帧策略以控制延迟，因此负载不足时会丢弃中间帧，不能把回调数量当作源视频帧数。

预测框只供短时画面连续性提示。涉及告警、统计或安全联锁的业务规则，应明确是否只接受 `observed=true` 的真实观测；不要把预测框计入人员检测 Recall/Precision，也不要把图像框坐标当作地面坐标或三维位置。输出的运行计数不代表准确率，仍需现场标注数据验证。

如需让其他设备通过网络调用，应由集成侧将 SDK 包装成符合现场鉴权、超时和消息协议要求的服务；本文接口本身是 Python 回调和命令行/文件接口。
