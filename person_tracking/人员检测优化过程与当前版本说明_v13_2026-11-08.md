# 人员检测优化过程与当前版本说明

## 1. 目标和边界

本模块的当前目标是从四路起重机现场视频中检测人员，并在短时漏检或遮挡时尽量保持轨迹连续。当前训练任务是单类别 `person` 检测，未在这一训练中学习安全帽、工装、吊钩、吊物类别，也没有把人员与吊物关系作为 YOLO 训练标签。

检测模型负责回答“当前画面是否有人员以及人员框在哪里”；跟踪器负责在相邻分析帧之间关联框；业务告警还需要结合 ROI、吊物位置、人员脚下地面和相机标定结果。三者不能用一个 mAP 数字互相替代。

## 2. 优化主线

### 2.1 先修正标注口径

早期数据中出现过把胳膊、腿或孤立肢体单独标成一个人的情况，也存在人员框过宽、漏包可见部分、吊钩或背景误标为人的问题。后续复核统一采用以下口径：

1. 每个可确认人员只标一个紧致外接框，覆盖该人员在画面中可确认的全部可见部分。
2. 被结构、吊物或其他设备部分遮挡但仍能确认是人的目标，仍标一个框；不猜测不可见人体轮廓。
3. 无法确认的孤立胳膊、腿、头盔或远处小块，不单独标为人，按排除或确认无人处理。
4. 吊钩、钢丝绳、工件、反光、背景文字和设备不标为人员；确认无人帧保留空标签。
5. test 成员和标签在每轮修订后重新锁定，训练和选权只使用 train，早停使用 val，test 不参与训练、调参或选权。

标注导出前保存审核记录、分集成员、图像/标签指纹和排除清单，避免网页中的临时修改直接改变正在训练的数据。

### 2.2 按误差类型补样

仅增加随机图片不能保证召回率提高，因此补样围绕真实错误组织：

- D01/D04 吊钩、钢丝绳、工件和背景误检，加入全画面负样本；
- D03 便装和不同颜色衣服人员，补充工装外观之外的正样本；
- 吊物遮挡、结构遮挡、边缘截断、俯视、弯腰、远处小目标、多人交叉和运动模糊；
- 低置信度、短轨迹和空检测时段先作为候选，必须人工复核后才进入训练；机器候选框不是真值。

v13 训练集由 v12 基线和人工复核的 D03/D04 困难样本合并得到：D03 新增 43 张、D04 新增 72 张，合并后 1,278 个样本槽位，train/val/test=1,121/46/111。实际唯一图像为 train=975、val=46、test=111；test 继续封存。

### 2.3 模型和训练参数调整

模型选择为 YOLO11n，原因是参数量和计算量适合车载边缘盒，且已有 Ultralytics 推理、跟踪和导出链路。当前 v13 从 v12 best 初始化，但建立新的 AdamW 优化器，不恢复上一轮优化器状态。

主要参数如下：

| 项目 | 当前设置 |
|---|---|
| 模型 | YOLO11n，单类别 `person` |
| 输入尺寸 | 1280 |
| batch / workers | 2 / 0 |
| 优化器 | AdamW |
| 初始学习率 | `lr0=0.0001` |
| warmup bias 学习率 | `warmup_bias_lr=0.0001` |
| 训练上限 | 80 epochs |
| 早停 | patience=15 |
| 数据增强 | mosaic=0.25、scale=0.25，最后 10 轮关闭 mosaic |
| 随机性 | seed=42，deterministic=true |
| 设备 | RTX 3060 Laptop GPU，CUDA，AMP |

历史版本的作用和结论：

| 版本 | 主要改动 | 结论 |
|---|---|---|
| v7 | 修正原人员框和孤立肢体，重新冻结分集 | 标注质量改善，但同日验证 Recall 仍约 68.42% |
| v8 | 增加 D01 遮挡候选 | 同一 val 的 Recall 从 v7 的 68.42% 降至 52.63%，不能替换 v7 |
| v9 | 对原有人样本重新复核，保持无人图记录 | Precision 提高，但 Recall 仍不足，D02/D03 漏检明显 |
| v10 | 只对 D03 便装片段专项微调 | 新增片段拟合改善，但旧场景出现退化 |
| v11 | 原样本与 D03 新样本平衡训练，修正 warmup bias 学习率 | 新旧训练图表现改善，但遮挡开发集 Recall 退化到 40% |
| v12 | 混入遮挡、边缘截断、俯视补样 | 固定 val P/R 达到 85.71%/100%，但 val 只有 12 个框，不能作为独立验收 |
| v13 | 加入人工复核的 D03/D04 困难样本，保持 test 封存 | 当前候选模型，仍需新日期/新作业独立验证 |

### 2.4 v13 训练结果

v13 在第 24/80 轮因 patience=15 早停，最优权重为第 9 轮。训练器验证结果为：

- 最优轮次 Precision=92.244%；
- 最优轮次 Recall=99.172%；
- 最优轮次 mAP50=98.885%；
- 最优轮次 mAP50-95=61.665%。

第 24 轮末的 mAP50=98.885%、mAP50-95=56.390%。当前最优文件为 `runs/train/person_yolo11n_static_v13_hard_merged_20261108_r2/weights/best.pt`，SHA-256 为 `31e57f30756ff3dc6306238842c627610dfe9d47d62b45e01df5e14045410fcc`。

这些指标来自同日开发 val，val 只有 46 张图像和 12 个人员框；mAP 是跨置信度和 IoU 的综合指标，不能直接代表业务工作点的误检/漏检，也不能代表跟踪 ID 稳定性。正式验收还应在未参与训练和选权的新日期或新作业视频上固定阈值报告 Precision、Recall、漏检持续时间和事件级 Recall。

## 3. 运行时稳定性优化

### 3.1 全图检测和嵌套框抑制

D01 当前按整幅画面检测，ROI 只用于输出 `inside_roi` 标记，不把 ROI 外框过滤掉，避免相机移动或区域配置变化造成漏检。检测器输出多个高度嵌套框时，若小框至少 90% 面积落在大框内且面积不超过大框 65%，只保留大框；被抑制的小框不进入跟踪器，从而减少同一人员申请多个 ID。

该规则不能区分完全重叠的两名真实人员，需在多人遮挡画面上单独复核。它也不能替代负样本训练，吊钩或背景被识别为人时仍需加入全画面人工确认负样本。

### 3.2 BoT-SORT 跟踪、确认和显示滞回

四路相机各自维护独立的 BoT-SORT 跟踪器，使用卡尔曼预测、框匹配和稀疏光流运动补偿，不加载外观 ReID。新轨迹连续命中 3 次后才显示 ID；显示层使用置信度滞回，起始阈值为 0.20、保持阈值为 0.15；框坐标再经过平滑，但不会修改检测器原始框或 MOT 坐标。

当前配置为：

- `analysis_fps=10`；
- `lost_buffer_seconds=2.5`；
- 10 fps 下跟踪缓冲约 25 个分析帧；原视频 25 fps 时，2.5 秒约等于 62～63 个源帧；
- 超过 2.5 秒没有真实观测，旧轨迹关闭，人员重新出现后可能获得新的 ID。

### 3.3 遮挡期间的预测框

为了让回放画面在短时遮挡期间尽量连续，增加了显示层预测逻辑，配置为 `prediction_box_seconds=2.0`：

1. 只有已经确认的轨迹才允许生成预测框。
2. 使用最近两个真实观测框的坐标变化估计速度，采用常速度外推；没有足够历史速度时保持最后一个真实框位置。
3. 预测框最多存在 2 秒，使用橙色虚线并标记 `PRED`，在 `frames.jsonl` 中写入 `observed=false`、`predicted=true` 和 `prediction_age_s`。
4. 预测框不计入真实检测数量、Recall、Precision、`tracked_observations` 或 `mot.txt`；它只服务于画面连续性和短时轨迹提示。
5. 真实检测重新出现时，跟踪器继续尝试把它关联到原轨迹；预测框不能保证关联成功，也不能从不可见图像中恢复真实人体位置。

因此，2 秒预测窗口和 2.5 秒轨迹保留窗口是两个不同概念：前 2 秒可以在回放中画预测框，2～2.5 秒仍可等待真实框回来并尝试续接，但不再画预测框。超过 2.5 秒后应视为旧轨迹结束，不能把预测结果当作已确认人员。

## 4. 验证和验收路线

### 4.1 数据和模型验证

每轮训练执行以下检查：

1. 审核状态 `pending=0`，确认无人和排除帧有明确记录；
2. 校验图像、标签、manifest、分集成员和审计指纹；
3. 训练只读取 train，val 用于早停和选权，test 保持封存；
4. 每 5 轮读取 `results.csv` 输出 mAP50、mAP50-95 和截至当前最优轮次；
5. 训练结束后使用固定 conf/IoU 的项目验证器复评 P/R，并按相机、遮挡、截断、远处小目标分组统计；
6. 新日期或新作业视频建立独立 holdout，不能与训练帧或相邻时间片重叠。

### 4.2 跟踪和预测验证

跟踪验证不能只看 `tracks_created`。应建立带连续人工 ID 的视频片段，统计：

- 同一人员在无遮挡、短遮挡、多人交叉和重新出现后的 ID 保持率；
- 2 秒预测框的显示覆盖率、位置漂移和误延伸率；
- 超过预测窗口后是否正确进入未知状态；
- 嵌套框抑制前后重复框数，以及多人真实重叠时的漏合并；
- 25 fps 原始输入、10 fps 分析和边缘盒实际吞吐下的端到端延迟。

安全告警应优先使用真实检测和经验证的跨相机关联。预测框只作为短时视觉连续性和待确认状态，不能单独触发“有人在吊物下方”等高风险结论。

## 5. 当前交付和限制

当前交付包括 YOLO11n v13 最优权重、训练过程文件、v13 人员标注数据集、训练/标注审计、跟踪代码、配置和本说明。原始四路视频不纳入代码归档；推理回放属于运行产物，单独保存。

当前主要限制：

- v13 val 小且来自同日数据，不能证明新日期泛化；
- test 尚未用于指标评估；
- 训练是单类别人员检测，不包含安全帽、工装、吊钩、吊物和三维距离标签；
- H.264 源视频尾部可能存在参考帧缺失，顺序解码需记录实际可读范围；
- 预测框是模型外推，不是新的图像证据；遮挡过久、快速运动、摄像头移动或人员交叉时可能漂移或换 ID；
- 边缘盒最终是否满足四路同时运行，需要在目标芯片、正式码流和热稳定条件下实测，不能由 RTX 3060 训练指标推断。

下一步应先用独立视频完成遮挡分组和跟踪事件验收，再决定是否增加模型规模、输入分辨率、时序模型或调整相机安装角度。
