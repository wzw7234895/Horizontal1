# 人员持续跟踪数据标注指南

适用项目：`E:\横向项目-目标检测\person_tracking`。制定日期：2026-11-05。依据当前代码：YOLO11n 检测 + 每路独立 BoT-SORT，分析帧率 10 fps，不启用外观 ReID，丢失缓冲默认 2 秒。

**先按业务选择标注范围。** 本指南定义完整连续轨迹真值，供系统性跟踪评估使用。仅判断“吊物移动时风险区有人”，可先使用人员检测与区域时序事件；判断“人员与吊物伴行”则建议在事件时间窗内做短时对应，不要求长期或跨相机身份识别。具体选择及先做事件标注的方案见 [人员与工件同时移动的检测与跟踪选型说明](人员与工件同时移动_检测与跟踪选型说明.md)。

## 1. 与静态框标注的区别

持续跟踪标注的核心是：**连续帧中的人员框 + 同一人员始终一致的人工 ID**。

| 帧 | 画面中的人员 A | 画面中的人员 B |
|---|---|---|
| 1 | ID=1，框 A1 | ID=2，框 B1 |
| 2 | ID=1，框 A2 | ID=2，框 B2 |
| 3 | 部分遮挡，仍为 ID=1 | ID=2，框 B3 |
| 4 | 完全不可见，不输出观测框 | ID=2，框 B4 |
| 5 | 确认是 A 再出现，仍为 ID=1 | ID=2，框 B5 |

框的位置和尺寸会变化，人的人工身份不因此改变。ID 只是数据集中的身份编号，不需要姓名或人脸身份信息。

已完成的 442 张静态图片可以训练和评价人员检测器，但它们按约 30 秒间隔采样，不是适合判断逐帧身份关联的连续序列。持续跟踪需要另选连续片段。

当前 BoT-SORT 根据检测、运动和匹配规则关联人员，未加载 ReID 模型。带 ID 的连续标注主要用于跟踪评估、关联参数调整和错误定位；它不是给 YOLO 普通检测训练直接新增一个 `track_id` 输出类别。将来若增加外观 ReID，身份标签才可进一步用于该模型的数据准备。

## 2. 先选片段，再逐帧标注

### 2.1 通道和身份范围

| 相机 | 位置与安装组 | 标注范围 |
|---|---|---|
| D01 | 右侧人员侦测，大车 | 本路连续片段中的人员 |
| D02 | 副钩吊点，小车 | 本路连续片段中的人员 |
| D03 | 左侧人员侦测，大车 | 本路连续片段中的人员 |
| D04 | 主钩吊点，小车 | 本路连续片段中的人员 |

每个相机、每个片段单独管理 ID，可以从 1 开始编号。完整身份键建议为 `(sequence_id, camera_id, person_id)`。D01 的 ID=1 与 D02 的 ID=1 不表示同一个人，本轮不要求跨相机身份关联。

每个分析帧中，所有能够可靠确认的人员都应标注；不能只标模型已经框出的人员。无人帧也保留在序列中，表示该帧没有有效人员框，用来统计误报。

### 2.2 从哪些片段开始

可先用已有每路 30 秒演示片段练习；10 fps 时每路约 300 个分析帧，共约 1200 帧。后续按实际事件扩充片段长度和数量，不把第一批四路 30 秒当作完整验收覆盖。

应覆盖：人员走动和停留、多人交叉、进出画面、吊钩/吊物遮挡、部分与完全遮挡、边缘截断、远处小人、弯腰/蹲姿、大车/小车运动、振动和模糊，以及无人但容易把设备当人的情况。需要保留事件发生前、发生中和结束后的连续过程。

**片段划分要与现有检测数据划分保持一致。** 当前 `data/person_v1/sampling_plan.json` 将文件名时钟的 `15:50–16:00` 时间组分配为 train，因此现有 `15:57:20` 演示片段应作为开发片段。将来在这段所属数据上微调后，不能再把它当作独立测试视频。

按当前记录，可考虑四路 `16:02:00` 附近的片段作为 val 开发验证，其属于预留的 `16:00–16:10` 验证时间组。最终 test 片段可以分相机选择：例如 D01/D02/D03 的 `16:12` 附近、D04 的 `15:15` 附近；四路文件覆盖范围不同，无需强求同一时刻。实际选段前仍需核对视频覆盖、时间组边界空档和场景内容。

这些时刻来自现有文件名时钟及分组，仅表示开发划分依据，不表示四路曝光已严格同步。片段应落在对应组边界排除范围之外，禁止把相邻片段逐帧随机分入不同集合。

## 3. 与当前 10 fps 输出准确对齐

### 3.1 推荐的标注输入

推荐使用从原录像提取的 **1920×1080、没有模型框和 ID 叠加的分析帧序列**，帧选择与 `frames.jsonl` 完全一致。每张图从 `000001.jpg` 开始连续编号，并保存分析帧号、实际累计源帧号与 PTS 的映射表。

当前 `annotated.mp4` 默认缩放到 1280 像素宽，并叠加模型框和轨迹；它适合回看模型效果。标注输入应从原录像重新导出干净图像，保留原分辨率和原始内容。

实际例子来自 `runs/demo_20261105_161147/D01/frames.jsonl`：

| 标注/分析帧号（1 起始） | 源累计解码帧号（0 起始） | 视频 PTS / 秒 |
|---:|---:|---:|
| 1 | 68347 | 2740.000 |
| 2 | 68350 | 2740.120 |
| 3 | 68352 | 2740.200 |

标注工具中的序列第 1 帧，对应这里的分析帧 1，不是原录像第 1 帧。10 fps 是目标采样率，实际 PTS 间隔不一定每次都恰好为 0.100 秒；评估帧的选取以映射表为准。

也可标注原始视频的每个可解码帧，再依据同一映射表提取分析帧标签。需要先确认标注工具的解码帧序列与本程序一致，不能只根据“原视频 25 fps”推算对应关系。

### 3.2 帧率选取原则

第一轮按当前 10 fps 标注，适合评价当前运行方案。关键帧插值只用于减少画框操作，**最终导出仍需覆盖每个被评价的分析帧**。如果以后要评价 25 fps、快速运动下的关联或其他采样方案，需相应补齐帧和映射，不能直接沿用未覆盖帧的 10 fps 标签。

## 4. 人员框和 ID 的具体规则

| 现场情况 | 建议标注规则 |
|---|---|
| 同一个人行走、弯腰、蹲下、转身 | 框随姿态变化，ID 保持一致。 |
| 两个人交叉或位置互换 | 通过前后连续画面追溯身份，ID 跟随真实人员，不跟随左右位置。 |
| 部分遮挡 | 能可靠确认人员时，按统一的可见范围画框；保持原 ID，并记录部分遮挡属性。 |
| 完全遮挡 | 不凭空补画人员框；保存遮挡前后的同一身份关系，在工具中标记该区间无可见形状。 |
| 遮挡后再次出现 | 能根据完整视频确认同一人员时沿用 ID，无论遮挡是否超过当前 2 秒缓冲。 |
| 离开画面后重新进入 | 确认是原人员时沿用 ID；确认为新人员时分配新 ID；身份无法判断时标为待复核，不凭空确定身份。 |
| 人员进入/离开边缘，只显示部分身体 | 可可靠确认时，框住画面内可见范围，保留同一身份；记录截断属性。 |
| 只有头盔、肢体片段，无法可靠确认人员或边界 | 标记困难/待复核区间；若无法解决，记录忽略范围并在评估中统一处理，不能默认为确定无人。 |
| 相机移动或视角变化 | 人工身份保持真实一致；背景变化不是换 ID 的理由。 |
| 完全无人 | 保留该帧，无人员框；模型报出的人员框仍应计入误报检查。 |

**人工真值的 ID 不按程序当前的 2 秒失踪缓冲重置。** 否则会把程序长遮挡后换号的问题隐藏在标签里。当前程序没有 ReID，长遮挡/出画重入后可能换号，这是需要评价的能力边界。

框边界沿用现有静态数据的口径：可确认的画面内可见人员范围。全身可见时包含整个可见人体；遮挡、俯视和边缘截断时保持一致，避免混用“只标头盔”“可见人体框”和“估计被遮挡完整身体框”。如需改为补全完整人体的标注政策，应作为独立版本统一处理，并调整评估解释。

一个人同一帧只能有一个有效框；两个人同时出现时不能共用同一 ID。ID 可以不连续，但不要把一个已使用的编号重新分配给另一人员。

## 5. 推荐工具与操作流程

当前项目的 `review` 网页只支持静态检测框及无人确认，没有跨帧身份/插值功能。持续跟踪建议使用 **CVAT 的 Track 模式**，或其他支持视频轨迹的工具。工具可插值画框，但人工仍要逐帧检查遮挡、交叉和运动突变。

1. 每个相机、每个连续片段建立独立任务，导入干净帧序列或经对齐的视频。
2. 建立 `person` 标签；建议增加 `occluded`（遮挡）、`truncated`（截断）及待复核备注。人工 ID 通常由工具的轨迹编号承载，不要把每个人建立成不同检测类别。
3. 目标首次出现时创建一条 person 轨迹，调整后续关键帧的框；确认中间插值覆盖实际位置。
4. 遮挡、进出画、多人交叉、姿态变化或镜头突然移动处增加关键帧，并检查该事件覆盖的每一个分析帧。
5. 完全不可见区间标记无可见形状；在 CVAT 中通常通过轨迹的 Outside/不可见状态控制插值区间。确认再次出现的是同一人时，继续同一条轨迹，避免跨不可见区间插出虚构观测框。
6. 可以导入模型轨迹作为预标注，再人工纠正漏框、误框、拆分和合并身份；预标注里的模型 ID 不直接作为人工真值。
7. 导出工具原生轨迹格式保存关键帧和属性，再导出 MOT 格式供后续评估。插值后的框仍须逐帧检查。

身份无法确定的情况应留下明确待复核记录。若最终设置 ignore 区域/帧，评估器必须同步处理 GT 和预测；本项目尚未实现该适配器，不能仅从真值中删除困难人员就直接评价，否则附近预测可能被误计为 FP。

## 6. 保存格式与 MOT 对接

### 6.1 推荐保留的主标注信息

```text
sequence_id, camera_id, frame_id, person_id,
x1, y1, x2, y2, occluded, truncated, review_status
```

主标注中的帧号从 1 开始，坐标采用原始图像像素的 0 起始连续坐标。身份在同一序列内保持一致。另存 `frame_map.csv`，至少包含 `frame_id, source_frame, video_time_s, width, height`。

完整保存工具原生文件，避免仅保存转换后的文本而丢失遮挡、Outside、关键帧和待复核信息。

### 6.2 MOT17 风格真值

典型 `gt/gt.txt` 每行 9 列：

```text
frame,id,left,top,width,height,mark,class,visibility
```

例如同一人员在连续 3 帧完全可见：

```text
1,1,801,301,80,160,1,1,1
2,1,806,302,80,160,1,1,1
3,1,812,303,80,160,1,1,1
```

这里 `frame` 从 1 开始，`id=1` 是同一人；`mark=1` 表示参与评价，MOT17 的行人类别为 `class=1`。`left/top` 使用标准 MOT 的 1 起始坐标，例如主标注的 x1=800、y1=300 导出为 left=801、top=301；宽高仍为 `x2-x1`、`y2-y1`。

`visibility` 描述可见程度，例子的 1 仅对应已确认完全可见的情形。若工具默认填 1 而没有逐帧人工标可见比例，应在元数据明确“未测量可见比例”，不将该列当作遮挡等级真值；第一轮可保留人工遮挡属性，先评价总体跟踪指标。

YOLO 人员类别为 0，MOT17 行人类别为 1，导出时应明确转换。模型预测结果常用的 MOT 10 列格式与真值的 9 列格式不同，不能直接互换。

**当前代码坐标适配点：** `tracking.py` 写入的 `mot.txt` 帧号已经从 1 开始，但 left/top 直接取模型的 0 起始图像坐标。正式对接标准 MOT 评估时，需为预测 left/top 同样加 1；或在内部评估适配器中把 GT/预测统一到 0 起始。保留原输出，统一转换副本，避免只改真值一侧。

### 6.3 建议的目录

```text
tracking_annotations/
  annotation_policy.md
  split_manifest.json
  D01_val_clip01/
    img1/000001.jpg ...
    frame_map.csv
    seqinfo.ini
    annotations_native.*
    gt/gt.txt
    review_notes.json
  D02_val_clip01/ ...
```

`seqinfo.ini` 可记录序列名、图像目录、frameRate=10、真实帧数、图像宽高及扩展名。因为采样间隔可能受原片 PTS 影响，时间相关的失踪/重捕统计应读取 `frame_map.csv`，而不是只按帧号除以 10 推算时间。

## 7. 标完后的核验

1. 核对图像数量、原始尺寸、frame_map 和 GT 帧号完全对应；空帧仍保留。
2. 检查每帧 ID 唯一、每个 ID 只代表同一真实人员，人员交叉时没有身份互换。
3. 检查可见人员有框、完全不可见区间无虚构框，ID 在可确认重现时保持一致。
4. 回放带人工框和 ID 的视频，重点检查遮挡/交叉/进出画的前后过程；同时检查框宽高、边界和标注口径。
5. 检查训练、验证和测试按作业片段/时间组分离，新增连续标签与静态检测标签的划分协调一致。
6. 用一致的帧序列评价当前检测+跟踪输出，报告 IDF1、HOTA、ID switches，并结合检测召回和误报；失踪/重捕时间按 PTS 计算。

人工 ID=1 不需要等于程序 ID=1；评估器会进行身份匹配。评价的是同一个人是否被稳定关联，以及检测和定位是否正确，而不是人工与模型编号的数字是否相同。

当前项目能输出预测的 `mot.txt`，尚未提供连续轨迹标注界面、干净分析帧包导出或完整 MOT/HOTA 评估适配器。本指南定义后续准备与对接规则，没有自动生成或伪造连续身份真值。已完成的训练仅针对静态 `person` 检测，不包含连续身份标签，也未训练或评估跟踪器。
