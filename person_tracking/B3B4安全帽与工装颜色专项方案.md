# B3/B4 安全帽与工装颜色专项实现

## 当前范围

B3 检查人员是否佩戴安全帽；佩戴时判断帽色是否属于客户允许集合。B4 只检查工装**躯干部位**的颜色。两者先对画面中所有人员做识别；后续可通过 Python 接口传入各相机的警戒 ROI，用区域状态限制最终告警。

当前 v13 人员权重仍只有 `person` 类。新增模块已经提供专项检测器推理、人员关联、结果结构、时间确认、ROI 告警门控、样本复核和 YOLO 数据集导出；尚无人工核准的专项标签，也没有 B3/B4 训练权重，所以当前**不会输出已验证的帽色/工装颜色结论**。无权重或未设置客户颜色策略时，结果为 `unknown`，不会默认当作合规。

## 标签定义

`configs/b3b4_attributes.json` 是模板。`candidate_label_colors` 是待讨论的候选颜色名称，并不代表客户已认可；必须先按客户规定修改并冻结标签表。默认分类构造规则为：

| 类别 | 标注内容 | B3/B4 含义 |
| --- | --- | --- |
| `head_no_helmet` | 可辨认的头部区域，头上没有安全帽 | B3 未佩戴 |
| `helmet_<color>` | 安全帽本体紧致框，且能判断帽色 | B3 已佩戴及颜色 |
| `torso_<color>` | 工装胸背等躯干可见区域的紧致框 | B4 躯干工装颜色 |

一个人一帧可有一个 B3 属性框和一个 B4 属性框。B4 只框可辨色的可见胸背工装区域，不标腿、鞋或整个人体框。`other` 表示颜色可辨认、但不属于当前列出的具体候选色；遮挡、过小、反光过曝、模糊或颜色混杂到无法可靠判断时，属性保持未知，不得用 `other` 代替。只有整帧无法复核时才排除此帧；否则完成整帧检查，并省略无法判定的部位。只有明确看见未戴安全帽时才标 `head_no_helmet`；安全帽没有检出不等于未佩戴。

默认候选类别包含 blue/yellow/white/red/orange/green/black/gray/other。颜色名单目前仅作为标注和训练候选，尚未获得客户认可；在客户名单确定并冻结前，不得输出“符合/不符合客户颜色规定”的业务结论或告警。实际训练前应根据客户规则删减或重定义，避免把“other”未经确认当作允许颜色。颜色应按原图与现场对照确认；相机白平衡、照明色温和反光材料会改变图像颜色。

## 训练

训练入口只接受通过复核和数据审计的导出目录。类别未覆盖训练集或验证集时会拒绝启动。基线选择 YOLO11n、1280 像素输入，最多 80 轮、patience 15；这只是开发起点，当前未启动训练。

```powershell
& 'D:\Anaconda\envs\crane-person\python.exe' -m person_tracking.train_b3b4 `
  --dataset 'E:\横向项目-目标检测\Horizontal1\person_tracking\data\b3b4_yolo_export_20261110' `
  --out 'E:\横向项目-目标检测\Horizontal1\person_tracking\runs\train\b3b4_yolo11n_20261110' `
  --model yolo11n.pt --epochs 80 --patience 15 --imgsz 1280 --batch 4 --device 0
```

训练之后不能只看总体 mAP；应按 B3 未佩戴、各帽色、B4 各躯干颜色，以及相机、远近、遮挡和光照分别评估 Precision/Recall、颜色混淆、无法判定率和事件级告警误报/漏报。固定置信度和策略后，再用独立日期录像验收。

## Python 集成和输出

`run_person_tracking()` 的 `frame_enricher(frame, record)` 接收原始 BGR 全帧及本帧人员轨迹记录；`create_analyzer()` 创建属性识别器。识别检测器在整幅画面运行，之后按部件框与人员框的包含关系配对。未传 ROI 时仍执行识别，只报告 `warning_roi_not_configured`，不发区域违规告警；以后可在调用时通过 `roi_overrides` 传入各相机的归一化多边形。ROI 使用相机画面归一化坐标 `[0,1]`，当前入区点按人员框底中心计算。

```python
from person_tracking.api import run_person_tracking
from person_tracking.b3b4 import create_analyzer

analyzer = create_analyzer(
    "person_tracking/configs/b3b4_attributes.json",
    weights="person_tracking/runs/train/b3b4_yolo11n_20261110/ultralytics/weights/best.pt",
)

result = run_person_tracking(
    output_dir="person_tracking/runs/b3b4_demo",
    config="person_tracking/configs/cameras.json",
    camera_ids=["D02"],
    weights="person_tracking/runs/train/person_yolo11n_static_v13_hard_merged_20261108_r2/weights/best.pt",
    analysis_fps=10,
    roi_overrides={"D02": [[0.1, 0.2], [0.9, 0.2], [0.95, 0.9], [0.05, 0.9]]},
    frame_enricher=analyzer,
)
```

每个人新增 `b3b4.helmet` 与 `b3b4.workwear_torso`：包含 `status`（`compliant/non_compliant/unknown`）、`color`、部件置信度、部件框、连续帧确认状态、告警状态和门控原因。帧级 `b3b4_alerts` 只在同一已跟踪人员的违规类别连续 3 次确认后产生一次事件；短时预测框不是新的识别证据。带框回放会绘制头/帽、躯干框和状态；`frames.jsonl` 保存原像素坐标及结构化属性结果。

ROI 以外的人员仍有完整 B3/B4 识别结果供调试，但不会触发警戒区域告警。相机 ID、session、track ID 组成轨迹键；ID 不是跨相机身份。属性识别与当前警戒区域规则均须在现场标注视频和边缘设备上实测后才能投入安全告警。
