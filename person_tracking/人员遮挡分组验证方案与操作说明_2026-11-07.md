## 3. 标注入口与规则

标注查看页面：<http://127.0.0.1:8773/?status=all>。本批 180 张已完成，待标筛选为空是正常状态。

可打开这张人员图像核对已有标签：

<http://127.0.0.1:8773/?status=all&sample=D03_20261020T164014_f000101896_holdout>。

原图保留 1920×1080；可点击“查看原尺寸”检查小人。样本为本次新增，不需要重标原先已确认无人的历史训练图片。

1. **一人一个紧致可见框**：包住该人所有可确认的可见部分。明确属于同一人的头、躯干、腿可共同包入一个外接框，允许框内夹有遮挡物；不要每条胳膊、每条腿分别标 person，也不要推测不可见的完整人体框。
2. **可确认的遮挡人员照常标注**：不能因只露上半身而删除。无法确认属于人员的孤立肢体，画局部“忽略区域”；清楚可见的其他人员仍保留。完全不可见、只能从前后帧推测存在的人不计入当前帧检测真值。
3. **逐人选择遮挡程度**：无遮挡 0%；轻度 (0,25%]；中度 (25%,50%]；重度 (50%,75%]；极重度 (75%,100%)；无法判断。比例是人工估计的被遮挡人体投影面积占完整人体投影面积，只选档位，不要求画完整人体轮廓。
4. **逐人选择遮挡物**：吊物/吊运工件 `load`，结构/设备 `structure`，其他人员 `person`，其他 `other`，无法判断 `unknown`；可多选。`load` 用于能确认参与吊运的工件，静置背景材料不能直接据此声称为吊物遮挡。看不出遮挡物性质时选无法判断并备注。
5. **画面截断单独勾选**：出画、被画面边缘裁掉的部分不计入遮挡比例。遮挡和出画可能同时发生，应分别记录。
6. **远近独立判断**：按现场空间关系选远处、非远处或无法判断；没有可信距离证据时不强填“远处”。程序另按 720p 等效可见框高统计 `<32px`、`32–<64px`、`≥64px`；“远处小目标”同时要求人工远处标签且可见框高 `<64px`。近处重遮挡也可能只剩小框，不能仅由框小推出距离远。
7. 确认整幅图无人时点击“确认无人并保存”；有忽略区域而无可确认人员时，保存为“无可确认人员 + 忽略区域”，不等同于整帧无人。整张无法可靠标注才排除并填写原因，不能因模型困难而排除清楚的人员。

无人帧保留用于计算误检；不能仅保留模型有框或人工有人的图片。模型建议不会作为这批真值来源。

## 4. 固定评估口径

推理将同视场 16:9 原帧缩小到 1280×720，`imgsz=1280`，person 类，置信度 `0.10`，NMS IoU `0.60`；人工框与检测框按 IoU `≥0.50` 一对一匹配。重复检测不能重复命中同一人；优先匹配真实人员，再处理忽略区域。未匹配预测与忽略区的预测面积交比达到 0.50 时忽略，否则计 FP。

该设置模拟第三码流像素尺寸，不等同于已验证真实相机第三码流的编码质量、裁剪范围或曝光效果。检测仅覆盖全图，不启用 ROI 裁剪、跟踪预测补框、显示平滑或额外嵌套框抑制，目的是先量化检测器本身的漏检；与实时跟踪整套程序的显示结果应分开解释。

`Recall = TP / (TP + FN)`；总体另报 `Precision = TP / (TP + FP)`。输出包括：

- 各遮挡比例、吊物遮挡、结构遮挡、各相机、可见框尺寸、远近、截断，以及遮挡程度与遮挡物交叉组的 Recall。
- 每组 TP/FN、人员框数、正样本帧数、正样本时间事件组数；同一人出现多帧仍是多个人帧，不是多名独立人员。
- 无真值人员的组为 `not_verified`；不足 30 个人帧或不足 3 个时间事件组为 `limited`，即使 Recall 很高也不据此宣称达到 85%。这两个计数是覆盖提示，不是样本量充分性的统计证明。本批最多两个事件组，所有非空组仍属于有限证据。
- 多遮挡物可使同一人进入多个组，组间计数不能相加；分组 Precision 无法直接按真值遮挡属性分配，故只报告总体 Precision/FP。
- Wilson 区间仅供描述。相邻帧和同一作业中的人员相关，不能把它当作独立事件置信保证。

当前工具评估逐帧可见人员检测，不计算跨帧事件 Recall、持续漏检时长或完全遮挡人员位置。后者需要连续视频的人员 ID、出入画/遮挡事件及多相机证据，不能用本批静帧分组结果替代。

## 5. 操作命令

在 `E:\横向项目-目标检测` 的 PowerShell 中执行。已启动的页面可直接使用；关闭后可重开：

```powershell
.\person_tracking\run.ps1 occlusion review --dataset person_tracking/evaluation/occlusion_20261107/review --port 8773
```

查看人工进度：

```powershell
.\person_tracking\run.ps1 occlusion status --dataset person_tracking/evaluation/occlusion_20261107/review
```

本轮 `frozen_v1` 及结果目录已生成。以下为以后修订源标签后的操作示例，必须使用尚不存在的新目录；无需重做 175 张已确认无人图。待标样本、未确认的空标注、图像变化或来源时间冲突会阻止冻结：

```powershell
.\person_tracking\run.ps1 occlusion freeze --dataset person_tracking/evaluation/occlusion_20261107/review --out person_tracking/evaluation/occlusion_20261107/frozen_v2
```

使用相同数据和固定工作点比较 v7 best 与 v8 best。下面使用 CPU，只推理、不训练，避免占用 GPU；也可在 GPU 可用时将 `--device cpu` 改为 `--device 0`：

```powershell
.\person_tracking\run.ps1 occlusion evaluate `
  --dataset person_tracking/evaluation/occlusion_20261107/frozen_v2 `
  --weights person_tracking/runs/train/person_yolo11n_static_v7_corrected_20261107/weights/best.pt person_tracking/runs/train/person_yolo11n_static_v8_d01_occlusion_20261107/weights/best.pt `
  --device cpu `
  --out person_tracking/evaluation/occlusion_20261107/results_v7_v8_v2
```

每次 `--out` 必须是新目录，以保留可复查结果；不删除旧输出。每个模型会生成 `metrics.json`、`recall_by_group.csv`、`report.md`、`per_person.jsonl`、`predictions.jsonl`，顶层生成 `comparison.json`。冻结副本不能通过页面修改，需修改源标注并另建冻结版本。

新增录像前先查看当前是否还有可隔离时段。以下命令只生成计划：

```powershell
.\person_tracking\run.ps1 occlusion plan `
  --mode strict_group --guard-seconds 30 `
  --out person_tracking/evaluation/occlusion_20261107/next_strict_plan.json
```

其他日期录像到位后，用 `--config` 指定包含新路径和录像起始时钟的单独相机配置，`--clips` 指定新时段清单，优先运行 `occlusion plan --mode strict_group` 检查隔离，再按相同流程采样、人工标注、冻结和评估。`--evaluation-root` 默认扫描本项目 `evaluation/`。本轮旧时段清单已用于模型比较，不能换一个输出目录就当作新独立样本。凡根据本批结果选阈值、调模型或补训练后，本批只能继续作为开发验证；正式验收需另留新录像。
