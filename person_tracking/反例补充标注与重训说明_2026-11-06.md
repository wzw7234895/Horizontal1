# 反例复核与下一轮人员检测训练

标注地址：<http://127.0.0.1:8768>。本轮请使用此地址；8766、8767 是旧版本页面。

数据目录：`E:\横向项目-目标检测\person_tracking\data\person_v4_negative_review_20261106`。最近保存的三处人工修改已继承；原有人员框保留作为本轮编辑起点。

## 需要做什么

本轮复核 677 张训练/验证图片：train 560、val 117；123 张 test 沿用 v3 封存版本，禁止编辑，不参与训练或选权。图片总数仍为 800，没有额外采样或启动训练。

| 画面内容 | 正确操作 |
|---|---|
| 确实一个人也没有，包括设备、灭火器、红色标识等 | 点击“确认无人并保存”；程序保存空人员标签 |
| 同时有人和类似人的背景物 | 删除背景误框，框出所有真实人员，点击“保存当前标注” |
| 当前框把背景误认成人 | 删除误框；重新检查全图，确认有无漏掉的人后保存 |
| 模型没画框，但能明确看到人员 | 拖动添加人员框，再保存；不要按模型候选是否存在来决定是否有人 |
| 遮挡、模糊严重到无法可靠判断 | 使用“排除此帧”，避免把不确定人员当成确认无人 |

反例不需要创建 `non-person` 类别，也不需要给灭火器等背景物画“人员框”。当前任务仍只有 `0: person`；同图有人时，其他背景区域也会参与检测器的背景学习。全图确实无人，才可将整张图片作为空标签负样本。

人员框应尽量贴合约定的可见外接范围，避免大量包入背景；近距离俯视、背身、蹲姿、部分遮挡等真实人员仍需按统一口径标注。不要为了分数删除困难人员。

## 标注完成后的训练流程

完成后在对话中发送“反例标注完成”。届时先检查 pending=0、标签格式、负样本明确确认、图片/标签一致、时间组隔离及测试图片/标签未变化，再导出新版本。从公开 YOLO11n 重新初始化，避免恢复含旧误标的优化器状态；最多 80 轮、允许早停，并按之前约定每 5 轮报告当轮及当前最佳 mAP50/mAP50–95。

本轮保留 v3 的分组与集合成员，不把验证反例移入训练。数据导出应依据本轮 `provenance/initial_fingerprints.json` 和 `provenance/reference_samples.jsonl` 做审计。旧 `prepare_person_v2.py` 绑定更早的 test，`prepare_person_v3.py` 会重新选择分组，均不应直接用于此轮。

本轮审计/导出入口已准备好：`person_tracking/experiments/prepare_person_v4.py`。标注未完成时会拒绝执行；完成后使用以下命令创建独立新导出，不会启动训练：

```powershell
& 'D:\Anaconda\envs\crane-person\python.exe' -m person_tracking.experiments.prepare_person_v4 `
  --dataset 'E:\横向项目-目标检测\person_tracking\data\person_v4_negative_review_20261106' `
  --out 'E:\横向项目-目标检测\person_tracking\runs\annotation_check_20261106_v4' `
  --export 'E:\横向项目-目标检测\person_tracking\data\person_reviewed_v4_20261106'
```

该入口检查集合成员与分组一致、图像未被改动、所有训练/验证标签已确认或排除、负样本明确确认、封存测试标签与审核记录未改变；导出后再次比对图像/标签指纹，并检查导出期间源标注未改变。只有全部检查通过才写出训练入口需要的 `annotation_audit.json`，不触发模型推理或训练。

修正后的 val 标注会改变评估口径。可将现有 v3 最佳权重与下一轮候选权重都放在修正后同一 val 上比较，以区分标注修正和训练变化；val 仍是开发验证，不等于独立现场验收。独立测试或跨日期泛化结果需另行验证。

本轮设置 `require_complete_review=true`，防止误将尚未复核完的部分图片导出训练。相关标注/导出回归检查 18 项通过，包括固定集合、保留空标签反例、拒绝修改测试标签、排除图片记录，以及导出期间标注改变时禁止产生通过审计记录。本地服务已验证能够返回本轮样本和图片，123 张 test 标签与参考版本一致。训练尚未启动。
